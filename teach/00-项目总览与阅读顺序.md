# Windows-to-Linux 项目总览与阅读顺序

这篇是 `teach/` 目录的索引：说明仓库长什么样、每个文件负责什么、按什么顺序读。

## 为什么这么创建

`Windows-to-Linux` 解决的是一个具体问题：Windows 没有 `grep`、`ls`、`cat` 这些命令，用户要么装 Git Bash / WSL，要么退回 Python 写一次性脚本。项目把这件事收敛成一个纯标准库、零第三方依赖的命令行工具，入口固定为 `python main.py <指令> [参数]`，`git clone` 之后不需要装任何东西就能跑。

教程拆成 17 篇而不是一篇，有两个具体原因：

- **篇幅**。`w2l/commands/grep.py` 有 299 行、31 个测试用例、9 个选项，单独一篇都难写透，塞进一篇只会变成 API 罗列。
- **读者分层**。想用这个工具的人关心的是「怎么敲命令」，想改这个项目的人关心的是「指令怎么加、退出码怎么定、测试怎么写」。这两类人该读的篇目不同。

文件名格式 `<两位序号>-<原文件名>-<中文短语>.md`：序号决定阅读顺序，原文件名让读者能对回仓库里的真实文件，中文短语说明这篇讲什么。序号固定两位是为了以后在中间插一篇不用给后面的篇目重排。

## 这个文件是做什么

它是导读页，本身不是源码。负责三件事：给出仓库的真实目录结构、给出两条阅读路线、给出 17 篇之间的依赖顺序表。

不负责：讲某个文件的实现细节（那是 01～16 的职责）、复述 README 的内容（README 在项目根目录，本来就是对外说明）。

## 有什么用

- 第一次打开这个仓库的人，从这一篇知道有哪些文件、每个文件干什么。
- 准备改代码的人，从依赖表知道「动 `w2l/registry.py` 之前必须先看哪几篇」，避免改坏注册机制。
- 判断某篇教程是否值得读：目录里的序号和依赖表给出定位。

## 怎么用（过程教程）

### 第 1 步：确认当前能跑起来

```bash
cd E:\1\NULL\Windows-to-Linux
python main.py
```

预期输出（退出码 1，因为没给指令名）：

```
用法: python main.py <指令> [参数]

可用指令:
  grep  搜索包含 PATTERN 的行（GNU grep 风格子集）

查看具体用法: python main.py <指令> --help
```

### 第 2 步：看清仓库结构

```bash
cd E:\1\NULL\Windows-to-Linux
python main.py grep -rl "" .
```

这条命令会列出项目里所有文件（空模式匹配每一行）。实际结构是这样：

```
Windows-to-Linux/
├── main.py                 # 入口薄壳，只调 w2l.cli:main
├── w2l/
│   ├── __init__.py         # 包声明 + __version__ = "0.1.0"
│   ├── cli.py              # 分发层：帮助输出、编码、异常→退出码
│   ├── registry.py         # 注册表 + @command 装饰器
│   ├── context.py          # RunContext（cwd / stdout / stderr / stdin）
│   ├── errors.py           # UsageError / CommandError
│   └── commands/
│       ├── __init__.py     # load_all() 自动导入子模块
│       └── grep.py         # grep 实现（299 行）
├── tests/
│   ├── conftest.py         # run_grep 辅助函数 + sample_tree fixture
│   └── test_grep.py        # 35 个用例
├── .github/workflows/ci.yml
├── .gitignore
├── pyproject.toml
├── README.md               # 对外说明与演进路线
├── AGENTS.md               # 项目守则
├── cron.md                 # 开发任务的 cron prompt
├── AI/                     # 脚本、进度、锁、任务 prompt
└── teach/                  # 本教程目录
```

### 第 3 步：选一条阅读路线

**路线 A · 想用这个工具**（按顺序读，读完就能上手敲命令）

1. `12-README.md-项目说明与路线.md` — 先看对外能力清单
2. `01-main.py-入口薄壳.md` — 入口长什么样
3. `07-w2l-commands-grep.py-检索实现.md` — grep 的 9 个选项到底怎么表现
4. `10-gitignore-版本控制边界.md` — 哪些文件不该提交

**路线 B · 想改这个项目**（按顺序读，读完能自己加指令）

1. `00-项目总览与阅读顺序.md`（本篇）
2. `01-main.py-入口薄壳.md` → `02-w2l-cli.py-分发层.md` → `03-w2l-registry.py-指令注册表.md`
3. `04-w2l-context.py-运行上下文.md` → `05-w2l-errors.py-异常与退出码.md` → `06-w2l-commands-指令自动发现.md`
4. `07-w2l-commands-grep.py-检索实现.md` — 唯一一份完整实现，是模板
5. `08-tests-测试怎么写怎么跑.md` — 加指令必须配测试
6. `13-新增一个指令的完整过程.md` — 走一遍全流程
7. `16-cron任务与定时推进.md` — 如果你要跟自动任务协作
