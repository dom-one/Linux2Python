# 新增一个指令的完整过程

这篇是从零到 `ls` 指令上线的完整操作手册，每一步都给命令和验证方式，可以照着做。

## 为什么这么创建

项目的一条硬约束是「一个新指令 = `w2l/commands/<名字>.py` 一个文件 + `tests/test_<名字>.py` 一个文件，主干不动」（`AGENTS.md` 第 3 节）。这条约束决定了流程必须是**加文件**而不是**改文件**：改主干意味着每次都有合并冲突，也意味着新指令的作者需要读懂四层架构才能动手。

所以整个流程被设计成「照抄模板 → 改细节 → 跑测试 → 提交」四步，每一步都能独立验证。文档写全流程而不是只给骨架，是因为这个流程里最容易出错的地方不是代码，是**约定**：

- 忘记用 `@command` 装饰 → 指令存在文件里但 `python main.py` 里看不到。
- 忘了写 `build_parser()` → argparse 的错误信息里 `prog` 会变成脚本路径。
- 退出码用错 → 命中类指令返回 0 会让 CI 判断失效。
- 只写正常路径测试 → 错误路径炸在用户面前。

**为什么先写测试再写实现。** 这个项目的用例是行为契约（`tests/` 里 31 条用例把 BRE/ERE 差异、退出码语义、二进制处理都钉死了）。先写测试能强迫你把「这个指令到底应该怎么表现」想清楚，尤其是退出码和错误消息这两件用户能直接感觉到的事。

**为什么一定要跑 `python main.py`（不带参数）。** 指令模块是被自动导入的（`w2l/commands/__init__.py`）。新模块有语法错误或导入期报错时，`python main.py grep --help` 也可能过，但 `python main.py` 是最直接的启动检查。

## 这个文件是做什么

这不是源码文件，是操作手册。它覆盖的完整流程：

1. 确定指令名、选项、退出码语义
2. 写 `w2l/commands/ls.py`
3. 写 `tests/test_ls.py`
4. 跑测试
5. 补 README 文档
6. 提交

每一步都有「怎么验证」，避免出现「写完了但不知道对不对」。

## 有什么用

- 第一次参与这个项目的人，照着走一遍就能独立加出指令。
- 忘了某个约定（比如 `prog` 写法、退出码）时，这里能查到。
- 把 `AGENTS.md` 里分散的几条规则（加指令步骤、测试要求、提交要求）串成一条可执行的路径。

## 怎么用（过程教程）

### 第 1 步：定清楚 `ls` 的行为契约

动手写之前，先把这几件事定下来：

| 决定项 | 本篇的选择 | 理由 |
|---|---|---|
| 指令名 | `ls` | 和 Linux 同名，用户不用查 |
| 参数 | `paths`（0 到多个，默认当前目录）、`-a` | `ls` 最常用的两个形态 |
| 排序 | 按名字排序 | 输出要稳定，测试才能断言全等 |
| 退出码 | 成功 0；参数不是目录 → `UsageError` → 2 | 「不是目录」是用法错误 |
| 输出流 | `ctx.stdout` | 正常输出走 stdout，错误走 stderr |

如果开发任务同时也在做 `ls`（`AI/阅读进度.md` 的命令队列第 1 项就是它），两个人会撞车。撞了以后按「一次提交一件事」的规矩，谁先提交谁算数，另一方 rebase。

新建 `w2l/commands/ls.py`，内容：

```python
"""ls：列出目录内容。"""

from __future__ import annotations

import argparse
from pathlib import Path

from ..context import RunContext
from ..errors import UsageError
from ..registry import command


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(
        prog="python main.py ls",
        description="列出目录内容",
        formatter_class=argparse.RawDescriptionHelpFormatter,
        epilog=(
            "示例:\n"
            "  python main.py ls\n"
            "  python main.py ls -a .\n"
            "  python main.py ls w2l\n"
        ),
    )
    parser.add_argument("paths", nargs="*", help="要列出的目录，默认当前目录")
    parser.add_argument("-a", "--all", action="store_true", help="包含以 . 开头的隐藏项")
    return parser


@command("ls", "列出目录内容", build_parser)
def ls(args: argparse.Namespace, ctx: RunContext) -> int:
    for raw in args.paths or ["."]:
        path = Path(raw)
        if not path.is_dir():
            raise UsageError(f"{path}: 不是目录")
        for entry in sorted(path.iterdir(), key=lambda item: item.name):
            if not args.all and entry.name.startswith("."):
                continue
            ctx.stdout.write(f"{entry.name}\n")
    return 0
```

四个必须照抄的地方：

- `prog="python main.py ls"` —— 出现在 `--help` 和错误信息里。
- `@command("ls", "列出目录内容", build_parser)` —— 名字、说明、解析器工厂。
- 函数签名 `(args: argparse.Namespace, ctx: RunContext) -> int`。
- 正常输出用 `ctx.stdout.write(...)`，不要用 `print`。

### 第 5 步：写测试

新建 `tests/test_ls.py`：

```python
import io

import pytest

from conftest import _Tty
from w2l.commands.ls import build_parser, ls
from w2l.context import RunContext
from w2l.errors import UsageError


def run_ls(argv, cwd):
    namespace = build_parser().parse_args(list(argv))
    out, err = io.StringIO(), io.StringIO()
    ctx = RunContext(cwd=cwd, stdout=out, stderr=err, stdin=_Tty())
    code = ls(namespace, ctx)
    return code, out.getvalue(), err.getvalue()


def test_ls_lists_names(tmp_path):
    (tmp_path / "b.txt").write_text("x", encoding="utf-8")
    (tmp_path / "a.txt").write_text("y", encoding="utf-8")
    code, out, err = run_ls([str(tmp_path)], tmp_path)
    assert code == 0
    assert out == "a.txt\nb.txt\n"
    assert err == ""


def test_ls_hides_dotfiles_by_default(tmp_path):
    (tmp_path / ".hidden").write_text("x", encoding="utf-8")
    (tmp_path / "visible.txt").write_text("y", encoding="utf-8")
    code, out, _ = run_ls([str(tmp_path)], tmp_path)
    assert code == 0
    assert out == "visible.txt\n"


def test_ls_all_includes_dotfiles(tmp_path):
    (tmp_path / ".hidden").write_text("x", encoding="utf-8")
    (tmp_path / "visible.txt").write_text("y", encoding="utf-8")
    code, out, _ = run_ls(["-a", str(tmp_path)], tmp_path)
    assert code == 0
    assert out == ".hidden\nvisible.txt\n"


def test_ls_default_is_current_directory(tmp_path):
    (tmp_path / "only.txt").write_text("x", encoding="utf-8")
    code, out, _ = run_ls([], tmp_path)
    assert code == 0
    assert out == "only.txt\n"


def test_ls_not_a_directory_is_usage_error(tmp_path):
    target = tmp_path / "a.txt"
    target.write_text("x", encoding="utf-8")
    namespace = build_parser().parse_args([str(target)])
    ctx = RunContext(cwd=tmp_path, stdout=io.StringIO(), stderr=io.StringIO(), stdin=_Tty())
    with pytest.raises(UsageError):
        ls(namespace, ctx)
```

三类用例都覆盖了（`cron.md` 第 3 节的要求）：

- 正常路径：`test_ls_lists_names`
- 选项组合：`test_ls_hides_dotfiles_by_default` / `test_ls_all_includes_dotfiles`
- 错误路径：`test_ls_not_a_directory_is_usage_error`

注意 `run_ls` 是照着 `tests/conftest.py` 里 `run_grep` 的形状写的。`conftest.py` 里已有的 `run_grep` 是 grep 专用的，通用做法是把 `run_grep` 改名成 `run_command`，让所有指令共用——不过那会动到已有文件，属于另一次改动。

### 第 10 步：两个已知缺口

做 `ls` 的时候有两个 Windows 特有的问题，按需要取舍：

- **隐藏文件语义。** 这个实现把「以 `.` 开头」当隐藏。Windows 上真正的隐藏是靠文件属性（`attrib +h`），跟文件名无关。Python 3.11 起有 `Path.is_hidden()`，但项目支持 Python 3.10，所以现在不能用它。要同时覆盖两种语义，得自己查 `GetFileAttributesW`——超出「纯标准库零依赖」的舒适区。
- **多参数输出没有分隔。** `python main.py ls w2l tests` 会把两个目录的内容连着输出，没有 GNU `ls` 那种空行分隔。加一行空行是很小的改动，但要记住它会影响测试断言。
