  3. 进交互 REPL 的命令块（裸 `python`/`python3`/`py -3`）默认跳过，按 `&&`/`;`/`|` 分段判定，`cd X && python` 也挡得住

### 2026-11-18 find.py 与 GNU 的三处缺陷（本轮实测）

给 `w2l/commands/find.py` 写教程时，用 61 个场景与 Git Bash 的 GNU findutils 4.10 对拍，
查出 3 处是**实现缺陷**（不是有意取舍），源码范围属开发任务，本轮按只读原则没动：

| 现象 | 根因 | 位置 |
|---|---|---|
| `-exec echo A{}B \;` 只输出路径，`A` 和 `B` 丢了；一个参数里多个 `{}` 只替换第一个 | `_expand_placeholder` 把整个参数替换掉了，没保留 `{}` 两侧的文本 | `w2l/commands/find.py` 第 737~746 行 |
| `-print -o -name '*.md' -print` 把 `notes.md` 打印两遍（GNU 只一遍） | `_Or.evaluate` 少了「左半边是裸动作就短路」这个分支；`_And` 有，`_Or` 没有 | `w2l/commands/find.py` 第 129~132 行 |
| 管道里输出是 CRLF（GNU 是 LF），`grep -x` / `$(...)` 比较会对不上 | 没像 `tail.py`（502~508 行）和 `cat.py`（154~160 行）那样调 `reconfigure(newline="")` | `w2l/commands/find.py` 全文 |

另有 2 处与 GNU 不同但属有意取舍：`-exec` 不带 `{}` 时本项目会追加路径（GNU 不追加）、
`-exec CMD +` 不带 `{}` 时 GNU 报错而本项目接受；`-printf` 遇到不认识的指令 GNU 会 stderr 警告而本项目静默。

实测脚本：`AI/脚本/_t701_probe_find_diff.py`（61 场景对拍）、`_t702_probe_find_exec.py`、
`_t703_probe_find_gaps.py`、`_t710_probe_find_or.py`。逐条结论见 `teach/24` 的「与 GNU findutils 4.10 的差异」一节。
