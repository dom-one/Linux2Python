这份文件是「补 teach 教程」定时任务的执行说明。每次触发的会话都读它，调度器里的 prompt 字段与本文件内容一致，本文件是唯一真相源。

工作区根目录：`E:\1\NULL\Windows-to-Linux`

产出目录：`E:\1\NULL\Windows-to-Linux\teach`

触发时间：每天 16:00（Asia/Shanghai）。开发任务每天 02:00 触发，两段相隔 14 小时。

**权威细则在 `AI/AGENTS.md`**：任务分工、错峰与互斥协议、取锁、进度追加格式、提交纪律、产出路径、硬红线。本 prompt 只规定执行顺序与写作口径，两处冲突时以 `AI/AGENTS.md` 为准。

--- 以下为 prompt 正文 ---

session：`mode=new`。

## 0. 读守则

读 `AGENTS.md`、`AI/AGENTS.md`、`AI/教程进度.md`。

从 `AI/教程进度.md` 的清单里确认哪些文件已经有教程、下一个该写哪篇。教程清单覆盖项目里的源文件、测试、配置文件、文档，以及 `AI/` 目录和两个定时任务本身。

## 1. 取锁与互斥检查

```bash
python AI/脚本/_t10_lock.py acquire --owner 教程
```

四个判定，按顺序做：

- 输出 JSON 里 `ok` 为 `false`：另一个任务正在写本工作区。本轮不做任何改动，直接进第 7 步收尾，报告写明锁被谁占着。
- 取到锁后，先补推上一轮遗留的提交：`git push origin main`。提示没有待推送内容属正常。网络不稳导致上轮推送失败时，提交会留在本地。
- 读 `AI/阅读进度.md` 末尾最近一条 tick 的时间戳。距今不足 30 分钟，说明开发任务刚跑过、可能还在收尾，本轮直接收尾，不并行开工。
- 前面三个判定都通过，才继续往下做。

被跳过的那一轮不追加 tick 日志，只在报告里写明跳过原因。

## 2. 选目标

列出项目里还没教程的文件，挑一个写一篇。挑选顺序：先补 `w2l/` 下的核心模块，再补 `tests/` 与根目录配置文件，最后补 `AI/` 与定时任务相关文件。

选题优先选读者卡住的地方：实现里逻辑绕、选项行为容易误解、跑起来会踩坑的文件。

## 3. 写作要求

每篇固定四个二级小节，标题逐字照抄：

```
## 为什么这么创建
## 这个文件是做什么
## 有什么用
## 怎么用（过程教程）
```

写作口径：

- 直述事实，不写套话、不用表情符号、不写鼓励话
- 结论要有依据：引用的文件路径、函数名、命令、选项都在项目里核对过
- 写之前先读对应源码，不凭印象写
- 「怎么用」里的命令要完整、可直接跑
- 保留 README 已有内容的价值，不整段复制 README

## 4. 落盘

文件名格式 `<两位序号>-<原文件名>-<中文短语>.md`，写进 `teach/`。序号按已有文件的序号往下排，中文短语说明这篇讲什么。

写完在 `teach/00-项目总览与阅读顺序.md` 的索引表里补一行，就地插入表格行，不重写整个文件。

## 5. 提交

```bash
git add teach AI/教程进度.md
git commit -m "docs(teach): 补充 <原文件名> 教程"
git push origin main
```

提交信息 UTF-8，一次提交一件事。提交前确认 `git status` 里没有本次范围之外的文件。

推送失败时（凭据或网络问题）本地提交保留，把「推送未成功」和报错原文写进报告，下个 tick 重推。

## 6. 追加进度

```bash
python AI/脚本/_t11_progress.py --进度 AI/教程进度.md --主题 "<原文件名> 教程" --理由 "<为什么这个 tick 写它>" --产出 "teach/<文件名>.md" --收获 "<关键收获>" --负面 "<翻车或判据误报，没有就写 无>"
```

再把教程清单里当前这一项的状态标为完成。进度文件的历史段落只能追加，不许重写。

## 7. 释放锁与报告

```bash
python AI/脚本/_t10_lock.py release --owner 教程
```

报告写三行：本 tick 写了哪篇、字数与路径、清单里下一个待写文件。

## 8. 收尾状态

本 tick 算完成的条件：教程文件已落盘、四个小节齐全、索引表已更新、提交完成、进度已追加、锁已释放。六条齐了才是完成态，任何一条没做，报告里写清缺哪一条。
